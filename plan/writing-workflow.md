# 论文写作与交接流程

2026-10-14补齐流程说明。CC此前补充的是`plan/results-map.md`及本地`results/summary/README.md`、`sec33_evidence_overview.md`的证据入口，没有另外新增写作流程文件。本文件将仓库已有规则和当前分工连成可执行步骤，不新增分析方案。

## 接手与限定任务

先读`AGENTS.md`、`HANDOVER.md`和`plan/progress.md`，检查Git与实际正文。完整科研工作区保留旧历史；用于重建远端的仓库从新历史开始，并携带小型结果文件。先判断所在环境，不把未上传的大表或数组当作实验结果尚不存在。检查已有修改，正文只改作者指定范围。

写作主线保持：1.3四站背景 → 3.1本站基准 → 3.2跨站绝对F1与相对目标本站的差距 → 3.3具体错误变化及其空间条件。没有独立Discussion或补充材料。当前1.3与3.1/3.2主体已存在，3.3、2.1模型原理、引言、结论及摘要仍未完成，以实际源码为准。

## 从证据到段落

1. 用一两句话确定本段要回答的读者问题，查`plan/results-map.md`定位已有底表。先检查能否复用，不以缺少亮点为由重启指标探索、重训或推理。
2. 修改结果前读实验协议、对应方法和实际summary；按模型、来源、目标、作物、预测身份连接。不从正文舍入值反算。新机器缺少大表或数组时，先按`plan/remote-storage.md`恢复相应资料，再核对数字。
3. 每个关键判断列出“对象/分母/相减方向/支持数据/例外/可写到什么程度”。写在`plan/`或核查记录，不写入论文。引言和解释段的文献判断先补`evidence/evidence-map.md`；复杂段落需要`plan/chapter-blueprints/`中的提纲。文献标题和已有BibTeX条目不等于证据。
4. 按`plan/style-guide.md`用连续段落写，先共性后差异，选少量能支持判断的数字。图表分工清晰，不逐行复述。1.3描述空间背景，不能提前安排分类难度或因果结论。
5. 回读该节与上下节：3.3必须接住3.2的具体比较；固定目标的空间格局不能单独解释来源差异。边界错误较多只作定位，不能代替模型优势、路径反例与实际错误贡献的判断。

## 保存、验证与交付

正常修改保存后不自动编译。作者要求编译、验证或最终检查时，按现有入口生成受影响表图，再编译并实际查看受影响页面。不重算无关科学统计，不以“图看起来正常”替代数值核对。测试放`scripts/test/`，生产脚本放`scripts/`。

核查只用Verified / Partially verified / Not verified，并注明本次范围和时点；历史核查不升级为全面复验。交付说明具体改了什么、证据在哪里、测了什么、还有什么限制。原文件和历史版本保留，归档有路径与SHA-256；编译、数据和归档留本地。未经作者指令不提交或推送。

推送前在新上传仓库运行`python -B scripts/manage_remote_repository.py check --history`。结果不是全部排除项；按机器规则保留小型文本，不推送旧历史、归档或资产包，不从完整旧仓库直接重推。
